## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| UI-SPEC locked exact Streamlit call signature without checking pinned version | 03-UI-SPEC.md locked `st.subheader("Email Drafts", icon=":material/drafts:")` verbatim, but the project pins `streamlit==1.59.2` (requirements.txt), and `icon` support on `header`/`subheader`/`title` was only added in a later Streamlit release (confirmed present in a stray 1.64.0 install, absent in the pinned 1.59.2 by reading `heading.py`'s signature directly). Caused a live `TypeError` crash the moment the developer opened the page. | advisory | Before locking an exact Streamlit (or any library) call signature in a UI-SPEC, verify the kwarg exists in the *pinned* `requirements.txt` version, not just current docs/Context7/latest release. |
| Local `.venv` has two shadowed Python interpreters | `.venv/bin/python`/`python3` symlink to a stray Homebrew Python 3.14 install (with streamlit 1.64.0), while `.venv/bin/streamlit`'s shebang correctly points at `.venv/bin/python3.13` (with the pinned streamlit 1.59.2, per `pyvenv.cfg`). Running `.venv/bin/python -c "import streamlit; print(streamlit.__version__)"` silently reports the WRONG version (1.64.0) vs. what the app actually runs (1.59.2, confirmed via `pip show streamlit` and via the actual traceback's file paths). | advisory | When checking installed package versions for this project, use `.venv/bin/pip show <pkg>` or `.venv/bin/python3.13` explicitly — never trust `.venv/bin/python` alone, it resolves to the wrong interpreter. Consider having the developer clean up the stray 3.14 symlinks outside of this GSD session (not attempted here — out of scope for this plan). |
| Opening-line prompt design didn't scope path-specific framing | 03-CONTEXT.md's D-05/D-06 defined which *facts* the AI opening line may reference (title/company only) but never addressed that the *rhetorical angle* also needs to vary by outreach path. Result: `client_sourcing` (a "let us help you" pitch) got a sponsorship-style "we want to learn from you" opener — grounded in real data, but business-nonsensical. Fixed by adding a `PATH_FRAMING` instruction map threaded through `generate_opening_line(..., path_slug)`. | advisory | Future AI-integration phases with multiple outreach angles/paths should explicitly scope prompt *framing* per path during discuss-phase, not just grounding-field scope. |

**Severity values:** `blocking` — resuming agent must pass understanding check before proceeding. `advisory` — important context, does not gate resumption.
