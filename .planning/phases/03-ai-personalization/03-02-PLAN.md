Functions:

Call `client.messages.create(model=MODEL, max_tokens=100, system=SYSTEM_PROMPT, messages=[{"role": "user", "content": user_prompt}])` inside a try block with one `except` branch each for `anthropic.APIConnectionError`, `anthropic.RateLimitError`, and `anthropic.APIStatusError` (note `APITimeoutError` subclasses `APIConnectionError`, so the connection branch covers it). Each branch returns `(None, <plain-language message>)` — one branch per known failure mode, plain language, never a raw exception or traceback, mirroring `bulk_match_people`'s status-code table. Join the response's text content blocks (`b.text for b in message.content if b.type == "text"`), then `.strip()`, strip a surrounding `"` character, and `.strip()` again (Pitfall 4 — defensive only; do not build a regex sanitization layer). An empty result returns `(None, <message>)`. Success returns `(line, "OK")`. This function never raises.
- `build_opening_line(client, title, company)` is the single decision point both fallback triggers flow through (D-07 sparse data and D-14 API failure share one fallback path). If `_is_sparse_title(title)`, return `(FALLBACK_LINE.format(company=company), "fallback")` without calling the API at all. Otherwise call `generate_opening_line`; on a `None` line return the same fallback tuple; on success return `(line, "ai")`. This function never raises.
- `should_warn_fallback_rate(fallback_count, total)` returns `False` when `total` is 0 (empty batch — no division by zero) and otherwise `fallback_count / total > FALLBACK_BANNER_THRESHOLD` (strictly greater, so an exact 50/50 split does not warn).

Never construct a client at module import time and never read `st.secrets` from this module — the key is passed in as a parameter by the caller, matching the repo's "read the secret once at the page/module top, pass it down" convention.
