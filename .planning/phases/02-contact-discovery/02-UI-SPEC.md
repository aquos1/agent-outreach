## Layout & Discovery Flow State System

This is the core interaction contract for Phase 2 — the executor should treat this table as authoritative for how the two-stage Find/Enrich flow renders and gates.

**Page structure (top to bottom, single page, no tabs/columns needed):**

1. `st.title("Contact Discovery")` + `st.caption` framing sentence.
2. Path selector: `st.selectbox` with `index=None`, placeholder shown, exactly 3 options in this order (PATH-01): "Club Sponsorship", "Productthon Sponsorship", "Client Sourcing".
3. Two free-text inputs: "Company type or industry" and "Target role" (`st.text_input`, both optional individually but **at least one must be filled** to enable search — see validation row below).
4. "Find Contacts" button (`st.button(type="primary")`) — disabled until a path is selected AND at least one free-text field is non-empty.
5. Result of stage 4 renders in place below the button (count/cost info, empty state, or error banner — mutually exclusive, see table below).
6. "Enrich & Continue" button — appears only after a successful non-zero Find Contacts result.
7. Result of stage 6 renders below it (results table or error banner).

All inputs (path selector, both text fields) remain visible and editable at every stage of the flow, including after a successful search or after enrichment — there is no "locking" of the form. Re-clicking "Find Contacts" at any point always re-runs the search fresh and discards any prior search/enrichment result on screen (no separate "New Search" control needed).

| Stage | State | Trigger / Condition | Blocking Behavior | Visual Treatment |
|-------|-------|----------------------|--------------------|--------------------|
| Form validation | Incomplete | No path selected, or both free-text fields empty | "Find Contacts" button rendered `disabled=True` — no error shown, just an inert button | Default Streamlit disabled button styling; no extra copy needed (self-evident from empty fields) |
| Find Contacts | Loading | Button clicked, request in flight | Nothing else on page changes yet | `st.spinner("Searching Apollo for matching contacts...")` |
| Find Contacts | Success, non-zero | Search + `has_email` pre-filter (DISC-02) + dedup exclusion (DEDUP-02) return ≥1 candidate | None — "Enrich & Continue" button becomes visible | `st.info` block, icon `:material/manage_search:`, count + cost estimate copy (see Copywriting Contract) |
| Find Contacts | Success, zero (empty state, D-12) | Same pipeline returns 0 candidates | None — no credits spent, inputs stay editable, no "Enrich & Continue" button rendered | `st.info` block (never `st.warning`/`st.error`), icon `:material/search_off:`, exact copy from D-12 |
| Find Contacts | Failure | Network error / Apollo 429 during search | Nothing below renders; user can edit inputs and retry immediately | `st.error`, icon `:material/cancel:`, see Copywriting Contract |
| Enrich & Continue | Loading | Button clicked, bulk_match request(s) in flight | Nothing else changes yet | `st.spinner("Enriching contacts with verified emails...")` |
| Enrich & Continue | Success | Enrichment completes, ≥1 verified-email contact returned | Terminal state for this page — enriched batch is written to `prospect` (status → `enriched`), ready for Phase 3 | `st.success` one-line confirmation + `st.dataframe` results table (Name/Company/Title/Email, D-11) |
| Enrich & Continue | Failure | Apollo 401/403/422/429/network error during `people/bulk_match` (includes the "out of credits" case per D-05 — Apollo's own error surfaces here, no separate balance check) | Table does not render; inputs and both buttons remain usable so the teammate can retry | `st.error`, icon `:material/cancel:`, see Copywriting Contract for exact per-code wording |

Icon assignments (extends Phase 1's Material Symbols table):
- Search action → `:material/manage_search:`
- Enrich action (spends credits) → `:material/bolt:`
- Empty result (not a failure) → `:material/search_off:`
- Failure (search or enrichment) → `:material/cancel:` (same as Phase 1's hard-block icon — both represent "this step did not succeed")
- Success / results ready → `:material/check_circle:` (same as Phase 1's Pass icon)
