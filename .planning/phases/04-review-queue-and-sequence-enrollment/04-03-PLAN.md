1. `build_contact_payloads(rows: list[dict]) -> list[dict]`: for each row with a truthy `email`, emit `{"first_name": ..., "last_name": ..., "email": ..., "organization_name": row.get("company"), "title": row.get("title")}`. When `first_name`/`last_name` are missing, derive them from `row.get("name")` by splitting on the first space (first token → first_name, remainder → last_name, empty string when absent) — rows drafted before 04-01 added the `last_name` column carry NULL. Rows without an email are omitted entirely; Apollo cannot create a contact without one.
2. `map_created_contacts(response: dict, rows: list[dict]) -> dict[int, str]`: build an email → prospect-id map from `rows` FIRST (lowercased emails), then walk `response.get("created_contacts", []) + response.get("existing_contacts", [])` and map each entry's lowercased `email` back to its prospect id, producing `{prospect_id: contact_id}`. Never match by list position — Apollo does not document order preservation across those two arrays (04-RESEARCH.md Pattern 2). Entries whose email matches no row are skipped silently.
3. `split_enrollment_outcome(response: dict, contact_to_prospect: dict[str, int]) -> tuple[list[int], list[tuple[int, str]]]`: enrolled = prospect ids whose contact id appears in `response.get("contacts", [])` (read each entry's `id` with `.get()`). skipped = every other prospect id in `contact_to_prospect`, paired with its reason: the value from `response.get("skipped_contact_ids", {})` when that structure is a dict and carries the id; the literal fallback string `"not confirmed by Apollo"` when the id is absent from both arrays or when `skipped_contact_ids` arrives as a bare list. Return reason strings verbatim — 04-UI-SPEC.md surfaces Apollo's own wording to the teammate, and 04-RESEARCH.md Pitfall 2 warns that spec.MD's `sequence_*` override-flag names are a DIFFERENT vocabulary from the response's actual reason codes, so never hardcode a comparison against them. Docstring must state D-07 explicitly: only ids Apollo's body confirms are Enrolled; an HTTP 200 is never sufficient.

4. `mark_contact_created(prospect_id: int, apollo_contact_id: str, db_path: str = "db/outreach.db") -> None` — `UPDATE prospect SET apollo_contact_id = ?, status = 'contact_created', updated_at = CURRENT_TIMESTAMP WHERE id = ?`.
